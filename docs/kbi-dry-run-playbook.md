# KBI Dry-Run Playbook

> **Goal**: 한 명의 KBI 운영 담당자가 30~45분 안에 9개 시나리오를 직접 클릭하여 시스템 전반의 사용 가능성을 확인한다. 각 시나리오는 **명시된 절차 → 기대 결과** 쌍이다. 결과가 다르면 즉시 `docs/dry-run-friction-log.md` 에 기록 (P0/P1/post-pilot 구분).

## 사전 준비

- backend (`make run-backend` 또는 `cd backend && uvicorn app.main:app --reload`) 동작 확인
- frontend (`cd frontend && npm run dev`) 동작 확인
- 브라우저 `http://localhost:3000` 접속, 로그인 (필요 시)
- 한 달치 ERP 발주 엑셀 (`Documents/ERP_샘플.xlsx`) 준비

## 시나리오 1 — ERP 업로드

1. 좌측 사이드바 **계획 등록** → **ERP 업로드** 페이지 진입
2. ERP 엑셀 파일 업로드 → 미리보기 표 확인
3. **저장** 버튼 클릭
4. **기대**: 토스트 "N건 등록되었습니다" + 등록 페이지로 자동 이동

## 시나리오 2 — 계획 등록 페이지 검토

1. **계획 등록** 메인 페이지에서 방금 업로드된 발주 목록 확인
2. 한 발주를 클릭하여 상세 패널 펼치기 — SQ / 색상 / 납기 / 사양 확인
3. **기대**: 모든 발주가 `planned` 상태로 표시되며 누락 컬럼 없음

## 시나리오 3 — 솔버 실행 (Stage1 → Stage2)

1. **Run** 버튼 (또는 단축키) 클릭하여 솔버 실행
2. 진행 상황 표시: "Stage1 진행 중 → Stage2 진행 중 → 완료"
3. **기대**: 30초 안에 솔버 완료, 간트차트가 자동으로 그려짐. 좌측 헤더에 `objective_value=<숫자>` 표시

## 시나리오 4 — Decision Card 동작

1. 간트차트의 한 배치 블록을 **클릭**
2. 선택된 행 **아래로** Decision Card 가 슬라이드-다운 (팝오버 아님)
3. **기대**:
   - Zone 1: 한 줄 요약 + 이동 가능 / 제약됨 / 불가능 pill
   - Zone 2: 가중치 상위 3개 막대그래프 (예: 납기 ████ 48K)
   - Zone 3: LLM 자연어 한 문장 ("이 배치는 납기 회피를 위해 ...")
4. 같은 배치 다시 클릭 → 카드 닫힘. 다른 배치 클릭 → 카드 교체

## 시나리오 5 — 제약 파라미터 편집 후 재실행

1. 우측 상단 사용자 메뉴 → **마스터 데이터** → **제약 조건** → **파라미터** 탭
2. 임의의 행(예: `4-1 stranding_min`) 값 변경 → **저장**
3. 토스트 "변경되었습니다" 확인 → 상단 **이력** 탭에서 방금 변경 기록 확인
4. 스케줄러로 돌아가 **Run** 다시 실행
5. **기대**: `solver_run.objective_value` 가 이전과 다른 값으로 변함

## 시나리오 6 — 베이스라인으로 리셋

1. **제약 조건** → **베이스라인** 탭
2. `BASELINE_phase0-initial_*` 항목 클릭 → "이 베이스라인으로 리셋" 버튼
3. 확인 모달에 변경 diff 미리보기 표시 → **확인** 클릭
4. **기대**: 토스트 "<태그> 베이스라인으로 리셋되었습니다.". 파라미터 탭으로 돌아가면 직전 변경이 되돌려져 있음.

## 시나리오 7 — 수동 드래그 + 사유 토스트

1. 간트차트에서 임의의 배치 블록을 다른 시간/설비로 **드래그-드롭**
2. **기대**: 즉시 이동 반영(블로킹 모달 없음) + 우하단에 60초 짜리 토스트 표시
3. 토스트의 4개 칩 (`납기 변경` / `현장 긴급` / `설비 고장` / `자재 부족`) 중 하나 클릭
4. **기대**: 1초 녹색 플래시 후 토스트 닫힘. 헤더의 "사유 미기록 N건" 배지가 1 감소

## 시나리오 8 — 노란 카드 (수동 조정 표시)

1. 시나리오 7 에서 이동한 그 배치를 다시 **클릭**
2. **기대**: Decision Card 가 **노란색 변형**으로 열림
3. 카드 내 disclosure 펼치면 `manual_override.reason="납기 변경"` + `snapshot_before` (원래 솔버가 정한 위치) 표시

## 시나리오 9 — 새 베이스라인 promote

1. **제약 조건** → **베이스라인** 탭 → **현재 상태를 베이스라인으로 승격** 버튼
2. 1단계 다이얼로그: 직전 베이스라인 대비 diff 미리보기
3. 2단계: 태그 입력 (`YYYY-MM-DD-HHmm-Jaewoo-튜닝1`), 승인 근거 작성, **확인**
4. **기대**: 토스트 "<changed_by> 베이스라인이 등록되었습니다.". 베이스라인 목록 최상단에 새 항목 추가.

---

## 마감 단계

- 9개 시나리오 모두 ✅ 인 경우 → `docs/dry-run-friction-log.md` 의 "결과 요약" 섹션에 "회수 0건" 기록 후 Week 6 종료.
- 1개 이상 ❌ → 즉시 friction log 에 ❌ 시나리오, 관찰된 동작, 기대 동작, 재현 단계 기록 → severity (P0 = pilot blocker / P1 = pilot annoyance / post-pilot) 부여.
