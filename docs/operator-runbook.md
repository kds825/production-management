# 운영자 런북 (Operator Runbook)

**대상:** KBI 코스모링크 생산 스케줄러를 매일 운영하는 스케줄러/현장 관리자.
**범위:** 일간 사용 흐름, 자주 마주치는 오류와 해결, 제약 편집/감사, LLM
설명자(Decision Card)의 의미, 수동 조정 시 노란 카드 의미 + 사유칩 사용법.

본 문서는 텍스트 전용 가이드입니다 (스크린샷 없음). UI 라벨은 한국어 그대로
표기합니다 — 화면에서 동일한 라벨을 찾으면 됩니다.

---

## 1. 일일 루틴

표준 흐름은 다음 5단계입니다. 한 사이클 약 5–10분.

1. **ERP 업로드** — 좌측 상단 "ERP 업로드" 클릭 → 당일 SAP 추출 엑셀 첨부.
   업로드 후 자동으로 Stage 1(작업지시서 생성)이 돌아갑니다. 결과 화면에
   배치 수, SM재공 매칭 건수, 외주 분류 건수가 표시됩니다.
2. **검토 (Stage 1 결과)** — 좌측 "배치 목록" 패널에서 신규 배치를 훑어
   납기 색상(빨강/주황/회색)과 외주 표시를 확인합니다. 외주로 잘못 분류된
   건이 있으면 우클릭 → "내제로 변환" 으로 수정 후 다음 단계로.
3. **Solve (Stage 2)** — "스케줄 생성" 버튼 → 솔버 실행 (보통 30초–3분).
   완료되면 우측 간트 차트가 새 배치로 채워집니다.
4. **Decision Card 검토** — 간트의 각 배치를 클릭하면 행 아래로 슬라이드
   다운으로 카드가 펼쳐집니다. 솔버가 왜 그 설비/그 시간을 골랐는지
   상위 3개 제약을 한국어 한 문장으로 보여줍니다 (§4 참조).
5. **저장 또는 수동 조정** — 만족하면 "확정" 버튼. 수동으로 옮기고 싶으면
   배치를 드래그 → 드롭 후 사유 칩 (지연납기 우선, 색상 묶음 우선 등)
   하나를 선택하고 "사유 저장". 사유 미입력 상태로 두면 우상단 배지에
   "사유 누락 N건" 카운트가 뜹니다 (§5 참조).

**팁:** Stage 1과 Stage 2는 분리 실행되므로, ERP 업로드만 하고 솔브를
나중에 돌릴 수 있습니다. 단 Stage 1 결과가 30분 이상 묵으면 SAP 변경분이
반영되지 않을 수 있으니 "Freeze & Rebuild" (Stage 1 재실행)을 권장합니다.

## 2. 자주 마주치는 오류와 해결

### 솔브 결과 INFEASIBLE (배치가 하나도 안 잡힘)

**원인:** 활성 제약이 너무 빡빡해서 모든 배치를 만족하는 해가 없습니다.
대부분 캘린더 (`6-*`) 혹은 자재수급 (`8-*`) 토글이 갑자기 켜진 경우.

**조치:**

1. 좌측 메뉴 "제약 관리" → 베이스라인 탭 → "현재 활성 제약" 목록과
   직전 베이스라인을 비교 (diff 버튼).
2. 직전 베이스라인 대비 켜진 제약을 임시로 끄고 솔브 재시도.
3. 어떤 제약이 원인인지 좁혀지면 어드민에게 보고 — 제약 자체를 영구
   끌지, 파라미터를 완화할지 의사결정 필요.

### 드래그가 거부됨 (배치를 옮길 수 없음)

**원인:** 옮기려는 슬롯이 하드 제약을 위반합니다 (예: 설비 호환성, 색상
규칙, 캘린더 휴무).

**조치:**

1. 화면 우측 하단 토스트의 **오류 코드** 를 메모합니다 (예: `EQ_INCOMPAT`,
   `COLOR_CHAIN`, `CALENDAR_OFF`).
2. 오류 코드를 어드민에게 전달 — 어드민은 `routes/schedules/cascade.py`
   에서 해당 코드의 거부 사유를 정확히 진단할 수 있습니다.
3. 임시 우회는 권장하지 않습니다. 거부에는 항상 도메인 이유가 있고,
   강제로 우회하면 후속 공정에서 더 큰 문제로 번집니다.

### Decision Card 가 빈 문장 ("활성 제약 없이 배정됐다.")

**원인:** 해당 배치가 우연히 모든 활성 제약 점수에서 0점으로 평가되었거나
(매우 단순한 입력), 솔버가 trace 행을 쓰는 데 실패했습니다.

**조치:** 정상 케이스로 간주해도 무방합니다. 같은 배치가 매번 빈 문장이
나오면 어드민에게 보고 (`solver_decision` 테이블에 행이 없을 가능성).

## 3. 제약 편집 — 권한·감사·베이스라인

- **편집 권한자:** 어드민(공장 관리자 + Samil PwC 엔지니어). 일반 스케줄러는
  읽기만 가능합니다.
- **감사 추적:** 모든 변경은 `constraint_config_history` 테이블에 자동 기록.
  어드민 화면 "변경 이력" 탭에서 누가/언제/무엇을 바꿨는지 시간순으로
  확인할 수 있습니다.
- **베이스라인 라이프사이클:**
  1. 현재 활성 상태가 만족스러우면 "베이스라인으로 승격" 클릭 → 스냅샷이
     `constraint_config_baseline` 에 저장됩니다.
  2. 이후 누가 잘못 바꾸면 "베이스라인으로 복원" 으로 즉시 되돌릴 수
     있습니다.
  3. 베이스라인은 여러 개를 보관할 수 있고, 각각에 라벨 (예: "2026Q2-안정")
     을 붙여 둘 수 있습니다.

상세 한글명·카테고리·기본값은 `docs/constraint-catalog.md` 참조.

## 4. LLM 설명자 (Decision Card) — 안전 규칙

- 카드의 한 문장 요약은 기본적으로 Anthropic Haiku 4.5 가 생성합니다
  (`backend/app/services/llm_providers/anthropic.py`).
- **다만 kiwipiepy 한국어 명사 필터** (`decision_narrator.py:57-93`) 가
  도메인 외 명사를 한 단어라도 잡아내면, 즉시 결정론적 템플릿 문장
  (`template.py`) 으로 교체됩니다. 즉, "외주 라인", "주말 근무" 같은
  허위 명사가 화면에 나오는 일은 구조적으로 막혀 있습니다.
- 카드 우측 하단에 옅은 회색으로 "(자동 요약)" 이 떠 있으면 LLM 출력,
  표시가 없으면 템플릿 폴백입니다. 둘 다 의미는 동일하며, 폴백이라고
  해서 잘못된 설명이라는 뜻은 아닙니다.
- 모든 호출은 캐시되므로 동일 세션에서 같은 배치를 다시 클릭해도 LLM
  비용이 거의 들지 않습니다.

상세는 `docs/llm-prompt-inventory.md` (프롬프트 본문 + 필터 규칙).

## 5. 수동 조정과 노란 카드

- 드래그로 배치를 옮기면 해당 배치의 `is_manually_adjusted` 플래그가
  `true` 가 됩니다.
- Decision Card 가 **노란 배경** (`var(--color-yellow-100)`,
  테두리 `var(--color-yellow-600)`) 으로 변합니다 — "이 배치는 솔버가
  아닌 운영자가 조정했다" 의 시각적 신호.
- 이동 직후 사유 칩 모달이 뜹니다. 미리 정의된 사유 (지연납기 우선,
  색상 묶음 우선, 설비 정비 회피, 기타) 중 하나를 선택해야 영구 저장
  됩니다.
- "기타" 선택 시 자유 텍스트 30자 이내로 부연 설명 가능.
- 사유를 입력하지 않고 화면을 닫으면 우상단 "사유 누락 N건" 배지에
  카운트가 누적됩니다 (`MissingReasonsBadge.tsx`). 일과 마감 전에 0으로
  비우는 것을 권장합니다.
- 사유는 `change_set_reason` 테이블에 기록되며, `routes/change_sets.py:
PATCH /{id}/reason` 으로 사후 수정도 가능합니다.

## 6. 모르는 증상이 나오면

먼저 `docs/troubleshooting.md` 의 검색 — 증상 텍스트(예: `EADDRINUSE`,
`INFEASIBLE`, `429`)로 grep 하면 거의 잡힙니다. 그래도 잡히지 않으면
화면 우상단 "버그 리포트" 버튼 → 자동으로 `Run-ID` (X-Run-Id 헤더값)
와 함께 어드민에게 전달됩니다. Run-ID 가 있으면 백엔드 로그에서 정확한
요청 흐름을 1초 안에 찾을 수 있습니다.
