# SpeedMaster 파생 경로 분석 — /24 vs /20 불일치

라운드: 2026-04-18
트리거: 사용자 지적 — "공정설비 및 규격 정리.xlsx" 의 `한 틀 시간 = F/G*24` 수식. 유휴시간(Mon-Thu 2h break) 을 고려하면 /24 는 틀렸다는 가설.

## 증거

### Excel 수식 (KBI 내부 문서)

`Documents/KBI코스모링크_PoC 관련 자료 정리.xlsx` 의 "공정설비 및 규격 정리" 시트:

```
한 틀 생산 기준 시간 [hr] = 틀당 연선 길이 [m] / 일 생산량 [m/day] × 24 [hr/day]
```

즉 **SpeedMaster speed 로 역산하면**:
`speed [m/min] = 일생산량 / (24 × 60)` = 1일 24h 연속가동 가정.

### 실제 DB 값 (2026-04-18 Supabase 기준)

```
eq         SQ  DB mpm  |  /24 exp  /22 exp  /20 exp
ST-54BO1   70   11.70  |    9.72    10.61    11.67  ← /20 일치
ST-54BO1   95   11.70  |    9.72    10.61    11.67  ← /20
ST-54BO1  120   11.70  |    9.72    10.61    11.67  ← /20
ST-54BO1  150   10.80  |    9.03     9.85    10.83  ← /20
ST-54BO1  185   10.80  |    9.03     9.85    10.83  ← /20
ST-54BO1  240   10.00  |    8.33     9.09    10.00  ← /20
ST-T6B0    16   25.00  |   20.83    22.73    25.00  ← /20
ST-T6B0    25   25.00  |   20.83    22.73    25.00  ← /20
```

**모든 ST-\* 연선 값이 `일생산량 / (20 × 60)` 로 정확히 일치**. 누군가 Excel /24 수식을 버리고 **/20 기준** 으로 수동 역산하여 DB 에 입력.

## Root cause

Excel 수식과 DB 값의 derivation 경로가 **다름**:

1. **Excel /24** — 보고/추정용 formula. 경영진 관점: "24h 기준으로 대충 몇 시간 걸릴까"
2. **DB /20** — 실무 입력값. 현장 관점: "하루 유효 20h 가동" 가정

/20 의 근거 추정:

- 연선 유효시간 가중평균 = (22h × 4 Mon-Thu + 14h Fri) / 5 = **20.4h/일**
- 또는 "8h 정규 + 8h 심야 + 4h 보조 = 20h" 같은 2교대 + 알파 경험치

## 시나리오별 정합성

| 데이터 경로              | Scheduler 결과                                          | 비고                          |
| ------------------------ | ------------------------------------------------------- | ----------------------------- |
| Excel /24 → speed        | 실가동 22h 에 /24 speed 적용 → **일 생산 91.7%** (과소) | 사용자 원래 가설대로 bug      |
| DB /20 → speed (현재)    | 실가동 22h 에 /20 speed 적용 → **일 생산 110%** (과대)  | 약간의 over-production        |
| KBI 실측 (이상)          | 모르는 값                                               | 측정 필요                     |
| PDF 이론 (PDF slot 역산) | 24 m/min 근처 (95SQ)                                    | 1안 원본 / 가용 capacity 초과 |

### 수치 검증 (95SQ ST-54BO1)

- 일생산량 14,000 m
- 현재 DB 11.7 m/min × 22h × 60 = **15,444 m/일** (110% over)
- /22 base 로 바꾸면 10.61 × 22 × 60 = **14,005 m/일** (일생산량과 일치)
- /24 base 로 바꾸면 9.72 × 22 × 60 = **12,830 m/일** (92%, under)

### 95SQ 5틀 48,500m pure work 비교

| base      | speed | pure hr |
| --------- | ----- | ------- |
| 현재 /20  | 11.7  | 69.1h   |
| /22       | 10.6  | 76.2h   |
| /24       | 9.7   | 83.3h   |
| PDF ideal | 22.5  | 35.9h   |

→ /20 → /22 로 바꾸면 **오히려 10% 길어짐**. PDF 와 여전히 큰 격차. PDF 원본은 이상적 capacity 가정.

## 결론

사용자의 "/24 이상" 관찰은 **Excel 수식 기준으로는 옳음**. 하지만 **실제 scheduler 에 적용되는 DB 값은 /20 기준** 이라서 **현재 scheduler 는 오히려 하루 10% 과대 생산**. 이는 연선 batch 가 물리적으로 가능한 것보다 빨리 끝나는 것을 의미.

**수정 방향 3 옵션**:

### Option A (현상 유지)

- DB /20 은 KBI 현장 실적 기반이라고 가정 → 변경 없음
- PDF 격차는 PDF 가 비현실적이라고 판단 → 수정본(1안 수정) 을 진실로 채택

### Option B (/22 로 정규화)

- "Mon-Thu 유효 22h" 엄격 일치 → DB speed 전체 × 20/22 = 91% 로 다운
- 결과: 모든 ST 배치 10% 더 길어짐. 납기 초과 악화.

### Option C (KBI 실측 확보 후 재파생)

- 가장 정확하나 현장 담당자 인터뷰 필요
- 필드 하나 추가: `speed_master.derived_from` ("실측" / "/20_avg" / "/22_exact" / ...) 로 출처 투명화

**권장**: **Option A 유지 + 투명화**. 이유: /20 기준이 PDF slot 과 대략 부합(연선 /20 → 95SQ 11.7 × 20 × 60 = 14,040m/일 ≈ 일생산량). PDF 원본의 더 높은 속도는 이상값일 가능성. **추가 작업**: KBI 확인 후 확정.
